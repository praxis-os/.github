# Support

## Where to go

| Need | Where |
|---|---|
| Bug report | Open an issue in the affected repository using the **Bug Report** template |
| Design or architecture proposal | Open an issue using the **Proposal** template |
| Documentation gap or improvement | Open an issue using the **Docs Request** template |
| Security vulnerability | **Do not open a public issue.** Follow the [security policy](SECURITY.md) |

## General guidance

- Use the structured issue templates. They exist to preserve signal quality and route your report to the right place.
- Check existing issues before filing a new one. Your problem may already be tracked.
- For questions about whether a contribution fits the project scope, open a proposal issue or comment on an existing one.
- For repository-specific bugs, file the issue in the affected repository. Use the organization-level tracker for cross-cutting concerns.
